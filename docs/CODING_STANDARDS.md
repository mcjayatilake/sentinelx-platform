# Coding Standards

## General

- Optimize for readability and explicitness over cleverness.
- No dead code, no commented-out code blocks, no TODOs without an issue
  reference.
- Keep functions small and single-purpose; prefer composition over deep
  inheritance hierarchies.
- Don't add abstractions, configuration flags, or extensibility hooks for
  requirements that don't exist yet.
- Write code and comments in English.

## Git workflow

- **Branches**: `feature/<short-description>`, `fix/<short-description>`,
  `chore/<short-description>`.
- **Commits**: [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `ci:`).
- **Pull requests**: small, reviewable, one logical change; CI must pass
  before merge; at least one approving review required.

## Python (backend)

- **Target version**: Python 3.13.
- **Formatting**: [Black](https://black.readthedocs.io/)-compatible
  formatting via `ruff format`. Line length 100.
- **Linting**: [`ruff`](https://docs.astral.sh/ruff/) (replaces
  flake8/isort/pyupgrade). Configuration lives in `backend/pyproject.toml`.
- **Type checking**: [`mypy`](https://mypy-lang.org/) in strict mode for
  `app/`. All new code must be fully type-annotated.
- **Imports**: absolute imports from `app.*`; no wildcard imports.
- **Async**: I/O-bound endpoints and database access use `async`/`await`
  throughout (SQLAlchemy async engine, async HTTP clients). Do not mix
  blocking calls into async request handlers — offload blocking work to
  Celery tasks or a thread pool.
- **Errors**: raise typed, specific exceptions; FastAPI exception handlers
  translate them to structured HTTP error responses. Never swallow
  exceptions silently.
- **Configuration**: all runtime configuration flows through
  `app.core.config.Settings` (Pydantic `BaseSettings`) — never read
  `os.environ` directly outside that module.
- **Logging**: use the configured structured logger
  (`app.core.logging.get_logger`); never use `print()`.
- **Testing**: `pytest` + `pytest-asyncio`. Tests live under `backend/tests/`
  mirroring the `app/` package layout. New behavior requires new tests.
- **Migrations**: schema changes go through Alembic
  (`alembic revision --autogenerate`); autogenerated migrations must be
  reviewed and edited by hand before merge, never applied blindly.

## TypeScript / React (frontend)

- **Framework**: Next.js App Router, React Server Components by default;
  add `"use client"` only where interactivity/state/browser APIs are
  required.
- **Language**: TypeScript in strict mode (`tsconfig.json`); no `any`
  without an explanatory comment and a linked issue.
- **Formatting**: [Prettier](https://prettier.io/) — run via `npm run
  format`.
- **Linting**: ESLint (`eslint-config-next` + TypeScript rules) — run via
  `npm run lint`.
- **Styling**: Tailwind CSS utility classes; shared design primitives live
  in `src/components/ui` (shadcn/ui conventions — copy-in components, not a
  package dependency). Avoid inline styles and ad hoc CSS files.
- **Data fetching**: React Query (`@tanstack/react-query`) for all
  server-state; colocate query/mutation hooks near the feature that uses
  them under `src/lib` or `src/features/*` as the codebase grows.
- **Components**: functional components only, named exports, one component
  per file, colocate component-specific types in the same file unless
  shared.
- **Testing**: component/unit tests with the project's configured test
  runner; test files colocate as `*.test.tsx` next to the source file.

## API design

- REST resources are nouns, versioned under `/api/v1`; breaking changes
  require a new version, not mutation of an existing contract.
- Request/response bodies are validated Pydantic schemas — never return
  raw ORM models from an endpoint.
- Pagination, filtering, and sorting follow a consistent query-parameter
  convention (`limit`, `offset`, `sort`) once list endpoints are
  implemented.

## Docker & infrastructure

- Dockerfiles use multi-stage builds; final images run as a non-root user.
- No secrets baked into images; all secrets are injected via environment
  variables or a secret manager at runtime.
- Kubernetes manifests are managed via Kustomize; environment differences
  live in `infrastructure/kubernetes/overlays/*`, never as duplicated base
  manifests.

## Security

- Follow [`docs/architecture/SECURITY.md`](architecture/SECURITY.md) for
  authorization, tenancy, and secrets-handling requirements — these are
  binding constraints, not suggestions.
- Never log secrets, tokens, or full credential material.
- All dependency additions go through the standard dependency-scanning
  pipeline once implemented; do not vendor unreviewed third-party code.
